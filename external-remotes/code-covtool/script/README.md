# Скрипты проекта CovTool

Эта директория содержит вспомогательные скрипты для разработчиков.

## Содержание

- [covex_analyze.pl](#covex_analyzepl) - Утилита для анализа эволюции формата LCOV файлов
- [generate_readme.pl](#generate_readmepl) - Скрипт для генерации `README.md` из POD документации
- [gen_expected_coverage.pl](#gen_expected_coveragepl) - Генерация/проверка ожидаемых файлов покрытия для тестов

### covex_analyze.pl

Утилита для анализа эволюции формата LCOV файлов между разными версиями LCOV.

**Описание:**
Скрипт анализирует изменения формата lcov-файлов между разными версиями LCOV.
Для каждой версии LCOV (начиная с указанной) копирует тестовый проект, собирает
его с покрытием, генерирует lcov-файл и сравнивает его с предыдущей версией.

**Использование:**

```bash
./script/covex_analyze.pl [опции]
```

**Основные опции:**

- `--project`, `-p` *path* - Путь к исходным файлам C/C++ проекта (по умолчанию: `./t/samples/src`)
- `--include`, `-i` *path* - Путь к заголовочным файлам (по умолчанию: `./t/samples/include`)
- `--start`, `-s` *version* - Начальная версия для анализа (по умолчанию: `1.16`)
- `--work-dir`, `-w` *path* - Рабочий каталог (по умолчанию: `lcov_analysis`)
- `--output`, `-o` *file* - Файл для сохранения результатов JSON
- `--verbose`, `-v` - Подробный вывод
- `--keep-repo`, `-k` - Не удалять клон репозитория LCOV после завершения работы
- `--skip-errors` - Пропускать версии с ошибками сборки вместо остановки анализа
- `--help`, `-h` - Вывод справки

**Примеры:**

```bash
# Базовый анализ с настройками по умолчанию
./script/covex_analyze.pl

# Сохранение результатов в файл
./script/covex_analyze.pl --output results.json --verbose

# Анализ с определенной версии
./script/covex_analyze.pl --start 1.14 --skip-errors
```

**Выходные данные:**

Генерирует отчет на STDOUT и JSON файл с результатами анализа, содержащий:
- Список проанализированных версий
- Различия в формате lcov-файлов между версиями
- Статистику изменений

### generate_readme.pl

Скрипт для автоматической генерации `README.md` из POD документации модуля `CovTool`.

**Описание:**
Скрипт извлекает POD документацию из `lib/CovTool.pm`, преобразует её в формат Markdown
и создает файл `README.md` в корне проекта с указанием версии модуля.

**Использование:**

```bash
# Автоматическое определение версии из модуля
./script/generate_readme.pl

# Указание версии вручную
./script/generate_readme.pl 0.0.5
```

**Примечание:**
Этот скрипт автоматически вызывается во время сборки проекта через `Build.PL`.
Версия может быть передана как аргумент командной строки или будет автоматически
извлечена из переменной `$VERSION` в `lib/CovTool.pm`.

**Требования:**
- Модуль `Pod::Markdown` должен быть установлен

**Пример:**

```bash
# Генерация README.md с автоматическим определением версии
./script/generate_readme.pl

# Генерация README.md с указанием версии
./script/generate_readme.pl v0.0.5
```

### gen_expected_coverage.pl

Скрипт для генерации и проверки "golden files" покрытия в `t/samples/coverage/*/expected/*.lcov`.
Используется разработчиками при изменениях логики `clip/remove/cleaning`, когда меняется ожидаемый LCOV.

**Использование:**

```bash
# перегенерировать ожидаемые файлы
./script/gen_expected_coverage.pl --write

# проверить, что ожидаемые файлы актуальны
./script/gen_expected_coverage.pl --check
```

**Примечания:**

- Скрипт не требует установки модуля в систему: сам настраивает `@INC` на `./lib` и `./t/lib`.
- Должен выполняться из корня проекта (или из любой директории — пути вычисляются относительно местоположения скрипта).

## Замечания

Скрипты можно запускать из любой директории - они автоматически определят правильные пути
к модулям и файлам проекта.
